# MR Admin

Стартовый шаблон админ-панели на React, Express и PostgreSQL. Интерфейс на русском языке, оформление на обычном CSS.

- **Обзор** — счётчики и пять последних обновлённых записей.
- **Записи** — создание, просмотр списка, редактирование, удаление, поиск и пагинация. Статусы: черновик, активна, в архиве.
- **Пользователи** — создание, просмотр списка, редактирование, удаление, поиск, пагинация и смена пароля. Последний администратор защищён от удаления и понижения роли.
- **Настройки** — название приложения, описание и контактный email.

Администратор имеет полный доступ. Редактор управляет записями, видит обзор и читает настройки. JWT действует восемь часов и хранится в HttpOnly-cookie. Смена пароля отзывает ранее выданные токены учётной записи.

## Запуск через Docker Compose

1. Скопируйте `.env.example` в `.env`. Задайте `POSTGRES_PASSWORD`, `JWT_SECRET` и данные первого администратора. Минимальная длина пароля администратора — 12 символов. Случайный JWT-секрет можно сгенерировать командой:

   ```sh
   node -e "console.log(require('node:crypto').randomBytes(48).toString('hex'))"
   ```

2. Из корня проекта выполните:

   ```sh
   docker compose up -d --build
   ```

3. Откройте [панель](http://localhost:8080) и войдите с `ADMIN_EMAIL` и `ADMIN_PASSWORD`.

При первом запуске Express применяет SQL-миграции и создаёт администратора. После первого запуска можно удалить `ADMIN_PASSWORD` из `.env`. Изменение переменных первичной настройки не меняет уже созданного пользователя. Данные PostgreSQL хранятся в томе `postgres_data`.

На сервере настройте HTTPS через обратный прокси на хосте и направьте запросы на `127.0.0.1:8080` (или выбранный `APP_PORT`). Установите `COOKIE_SECURE=true`. Прокси должен обслуживать приложение в корне домена или поддомена. Если требуется определять IP клиента для ограничения попыток входа, передайте приложению `TRUST_PROXY` со списком доверенных IP-адресов или подсетей прокси (через окружение контейнера). PostgreSQL остаётся во внутренней сети Compose.

Обновление — `docker compose up -d --build`. Состояние API и подключение к базе проверяются по `GET /api/health`. Перед обновлением схемы сделайте резервную копию базы.

## Локальная разработка

Нужны Node.js 24, npm и запущенный PostgreSQL. Создайте пустую базу, скопируйте `.env.example` в `.env` и укажите `DATABASE_URL=postgres://user:password@localhost:5432/mr_admin`, `JWT_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` и `COOKIE_SECURE=false`. Вместо `DATABASE_URL` можно указать стандартные переменные `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`.

Из корня проекта запустите команды в двух терминалах:

```sh
npm --prefix backend ci
npm --prefix backend run dev
```

```sh
npm --prefix frontend ci
npm --prefix frontend run dev
```

Vite выводит адрес панели и проксирует `/api` на порт 3000. При изменении порта Express задайте `API_TARGET` в окружении Vite. Чтобы запустить без Docker с одним HTTP-сервером, выполните `npm --prefix frontend run build`, затем `npm --prefix backend start`. Express отдаёт сборку и API с одного адреса.

## Как адаптировать

1. Добавьте новую нумерованную SQL-миграцию в `backend/migrations`. Уже применённые файлы оставляйте в истории и меняйте схему новыми миграциями.
2. Возьмите `backend/src/records.js` за пример ресурса. Подключите его после middleware авторизации в `backend/src/server.js`. Для доступа только администратора добавьте middleware `admin`.
3. Добавьте раздел в навигацию `frontend/src/main.jsx`. Для CRUD-таблицы используйте `frontend/src/collections.jsx` как пример конфигурации полей и действий. Цвета и правила оформления находятся в `frontend/src/styles.css`.

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/api/health` | Проверка подключения к БД |
| POST | `/api/auth/login` | Вход по email и паролю |
| POST | `/api/auth/logout` | Очистка cookie |
| GET | `/api/auth/me`, `/api/overview` | Текущий профиль и обзор |
| GET, POST | `/api/records`, `/api/users` | Список и создание |
| GET, PUT, DELETE | `/api/records/:id`, `/api/users/:id` | Просмотр, изменение и удаление |
| GET, PUT | `/api/settings` | Чтение и сохранение настроек |

Списки принимают `q` и `page`, возвращают `items`, `total`, `page` и `size`. API использует относительные адреса и cookie. Для POST, PUT и DELETE передавайте заголовок `X-MR-Admin: 1`, для JSON также нужен `Content-Type: application/json`.

Создайте пустой удалённый репозиторий, затем выполните в `mr-admin`:

```sh
git remote add origin <URL_репозитория>
git push -u origin main
```
